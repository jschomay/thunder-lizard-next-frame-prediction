Giving the net a memory (H15)

A LinkedIn commenter: "Temporal consistency requires recurrence." This page shows what that means, how it differs from what we have, and how it's trained.

1. A window vs. a memory

Today the net sees a window of the last 4 frames. Anything older is gone. A recurrent net also passes a memory to itself every tick: a stack of numbers it chooses what to write into and what to keep. Step through the ticks: a dino starts chasing at tick 2 (its target is invisible in the frames), and it matters at tick 9.

tick 2

2. What the memory is

Every cell already has a vector of 64 numbers (features) inside the net; see Inside the model. The memory is a second vector of 64 numbers per cell that survives to the next tick.

A ConvGRU decides, for every number, how much to rewrite. Two "gates" (numbers between 0 and 1, computed by small 3×3 convolutions from the new features and the old memory):

  • update gate z: how much to replace. 0 = keep the old memory, 1 = overwrite with the new.
  • reset gate r: how much of the old memory to look at while writing the new.

new memory = (1 − z) · old + z · candidate

Because the gates are 3×3 convolutions, neighbouring cells can pass memory along, e.g. as a dino walks. (ConvLSTM is a sibling with an extra gate; ConvRNN is the simple version without gates, which forgets fast.)

3. Training through time ("error through time")

With a window, each example is scored alone. With memory, we feed 8 ticks in a row and score every one. If tick 8 is wrong because something wasn't remembered at tick 2, the error flows backwards along the memory arrows and adjusts what gets written at tick 2. This is backpropagation through time; cutting it at 8 ticks is "truncated". Click a tick's error to see where it sends blame.

4. Our version

  • Added on top of the best model, not replacing it: it still sees 4 frames, plus the memory.
  • Warm start: the layer that feeds memory into the rest starts at zero, so the run begins exactly as the best model (checked) and learns to use memory from there. Same trick as the U-Net branch.
  • Training: 8-tick sequences, same frames per step as before. The memory starts empty at each sequence.
  • Cost: ~0.13M more weights. Each tick does a bit more work, and the app would have to carry the memory between ticks.
  • Measured by the scorecard: smear, static, dinos, scrolling, plus a planned "walk away and come back" continuity test. And how it feels to play.

6. Results

Both runs start from the same best model and train 3 more passes on the same data; the only difference is the memory. Rollouts: 24 held-out games × 150 ticks, the model on its own.

*One-step scores give the memory model an empty memory, which it never had in training, so they slightly understate it.

Second try (bigger memory, as the commenter suggested): an 89×89 memory canvas, about 2× the screen, trained on 128-tick sequences with a bot that walks out and comes back. Continuity: 70.0% vs 70.2% without memory (real game 95.4%). Smear got worse (86% vs 68%), and it's 3.6× slower. The memory was being used (later chunks had 11% lower loss), but remembering terrain barely matters to the training loss: only the single row revealed when you scroll back benefits.

Verdict so far: a small edge, not a clear win. Most of the improvement we first saw came from the extra training, not the memory. The memory still keeps dinos around a little better and smears a little less. It may matter more where we haven't tested yet: walking away and coming back (continuity), and training on sequences longer than 8 ticks (~0.6 s of game time).
