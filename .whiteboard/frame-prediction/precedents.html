Precedents: neural game engines

Each of these learned to stand in for a game or environment from recorded play. This page covers how each worked, how it compares to Thunder Lizard, and which ideas we're borrowing. Mark anything.

The shared idea

frames so far+action→learned model→next frame↺ fed back in

The term for this is a world model. The projects differ in three ways: what a frame is (pixels, compressed codes, or symbols), how the model generates (one shot, or diffusion's gradual denoising), and what the model is for (training an AI agent inside it, or letting humans play it).

World Models

Ha & Schmidhuber, 2018 · CarRacing, VizDoom
V: VAE squeezes a 64×64 frame into a small code z→M: RNN predicts the next z as a probability mix→C: tiny controller picks actions

The model never predicts pixels directly. It predicts in a compressed "latent" space and decodes to images only for viewing. The headline result: they trained the agent's controller entirely inside the model, then it worked in the real game. One lesson: the agent learned to exploit the model's mistakes, so they added a temperature knob that makes the model more random and therefore harder to cheat.

For us: our grid is already compact, so we skip the compression step. The temperature idea maps directly to sampling vs argmax (H5).

GameGAN

Kim et al. (NVIDIA), 2020 · Pac-Man, VizDoom
past frames + key→dynamics engine (LSTM)⇄memory module (remembers the map)→rendering engine: static layer + dynamic layer

The closest precedent to this project: a 2D grid game, learned from frames and key presses, playable afterward. It used a GAN, a generator trained against a critic that tries to tell real frames from fake ones. Two ideas stand out. It had an explicit memory, so the maze stayed consistent when you came back to a spot. Its renderer separated the static background from dynamic sprites, which also let them swap in new backgrounds.

For us: our terrain/entity layers are the same static/dynamic split, given explicitly instead of learned. Its memory addresses a problem we have too: terrain scrolling back into view.

GameNGen

Valenzano et al. (Google), 2024 · DOOM at ~20 fps
RL agent plays DOOM → millions of frames + actions→fine-tuned Stable Diffusion, conditioned on the last 64 frames + actions→next frame, about 4 denoising steps

A diffusion model starts from noise and refines it into an image over several steps. They started from a pretrained image model, which is the Hugging Face path for pixel games. Two lessons apply directly to us. First, the training data came from an AI agent rewarded for playing like a human, not random actions, because coverage matters (H6). Second, they added noise to the context frames during training so the model learned to correct its own small errors. That was the key fix for autoregressive drift. In short clips, human raters were only somewhat better than chance at telling real from generated.

For us: borrow context-noise augmentation for drift, the agent-generated data, and the blind human-rater evaluation (H7).

DIAMOND

Alonso et al., NeurIPS 2024 · Atari, CS:GO
agent acts in the world model→diffusion model predicts the next frame directly in pixels→agent learns from imagined experience↺ collect more real data

A diffusion world model used mainly to train agents. The agent learns Atari games mostly inside the model, using only about 2 hours of real gameplay. Their finding: keeping visual detail (pixels instead of compressed codes) mattered for the agent's performance. They also released a playable CS:GO model trained on 87 hours of human play.

For us: they gave up fidelity on purpose to get speed and stability, and that tradeoff applies to our model too. A future extension would be training a bot inside our model, which would close the loop.

Genie (1, 2, 3)

DeepMind, 2024–2025 · 2D platformers → 3D worlds
video tokenizer→latent action model: infers which "button" caused each change→dynamics transformer predicts next tokens

Trained on internet videos with no key logs at all. It invents a small set of discrete actions by noticing consistent kinds of change between frames, so after training you can "play" any image. Genie 1 had 11B parameters. Later versions produce interactive 3D worlds in real time.

For us: we have exact key logs, so we skip the hardest part. Its dynamics transformer over tokens is approach B at a very large scale.

Our niche: a symbolic grid makes this 1000× cheaper than pixel world models. It runs on a laptop, so we can do controlled experiments, like an A/B/C architecture comparison, that are expensive at pixel scale.

Ideas we're borrowing

  • Context noise augmentation (GameNGen): corrupt some cells in input frames during training to reduce drift. Candidate H8.
  • Temperature / sampling (World Models): H5.
  • Agent-generated data (GameNGen, GameGAN): the heuristic bot, H6.
  • Memory for revisited terrain (GameGAN): a later fix for edge cells scrolling in.
  • Blind human raters (GameNGen): H7.
