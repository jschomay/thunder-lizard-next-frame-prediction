How it works

Every part from the game to training, with the actual code and real recorded data. ■ built is working now; ■ planned comes next. No model has been trained yet; everything so far produces and checks data.

Glossary
kHow many past frames the model sees. k = 2 means the current frame plus the one before it. More history lets it infer rhythm and motion (H3).
batch (64)How many examples go through the model at once. The model adjusts after each batch, using the average error.
channelOne number per cell, like one color in an image. Our input has k × 50 + 5 channels per cell.
one-hotA category written as a row of 0s with a single 1 (GRASS = slot 3 on).
filter / conv layerA small learned weight table (3×3 × channels) slid over the grid. Each filter produces one new feature channel. A layer has many filters.
receptive fieldHow far a cell can "see" after stacking layers: 3×3, then 5×5, then 7×7, …
hyperparametersThe settings we choose (k, learning rate, epochs, batch size, loss weighting, width/depth), as opposed to the weights the model learns.
weightsThe numbers inside the filters. Training adjusts them. Everything else (sizes, k, batch) is chosen by us.
head / bodyThe body (backbone) is the shared stack of layers that builds features. A head is a small final layer that turns those features into one specific answer. Ours: a terrain head and an entity head (H11 would split the entity head into three).
logits / softmaxLogits are the raw scores a head outputs. Softmax turns them into probabilities that sum to 100%.
logprobThe (natural) log of a probability. Products of probabilities become sums, which keeps numbers stable.
cross-entropy lossThe training objective: −log(probability given to the true answer). It heavily punishes being confidently wrong. train/loss is its average.
argmax / samplingArgmax: take the most likely class. Sampling: a weighted random pick by probability (rolling the dice).
temperature / top-pKnobs that reshape the dice before rolling: temperature sharpens (<1) or flattens (>1); top-p drops the unlikely tail.
calibrationWhether predicted probabilities match reality: things predicted at 10% should happen about 10% of the time.
epoch / stepEpoch = one full pass over the training data. Step = one batch and one weight update.
validation / overfittingValidation = held-out episodes, never trained on. Overfitting = training loss improves while validation gets worse (memorizing instead of generalizing).
warm start / fine-tuningStart training from an existing model's weights instead of random ones (H4).
rolloutFeeding the model its own predictions tick after tick: playing inside the net.
U-Net / skip connectionA CNN that shrinks the grid to see wide, then grows it back. Skip connections carry full-detail features straight across to the output side.
error analysisSlicing the model's mistakes into categories until a pattern shows up (section 6).

1. The whole pipeline

2. One tick: what a training example is made of

The real game runs a 70 ms loop. The harness runs the same loop body on demand, with no clock, so 1,000+ ticks per second.

// harness/headless.ts — HeadlessGame.step(key)
if (key !== "NONE") keypressCb(...)   // same as a real keydown
awarenessSystem(dinoWorld)            // dinos notice things
movementSystem(dinoWorld)             // player + dinos move
deplacementSystem(terrainWorld)       // trampled grass
scoreSystem(dinoWorld)
lavaClock += 70                        // lava ticks every 50 ms
while (lavaClock >= 50) lavaTick()     //  → ~1.4 lava steps per tick
// harness/record.ts — one episode
obs[0] = observe()
for t in 0..T:
  key        = bot.act()
  actions[t] = key
  step(key)
  obs[t+1]   = observe()

The data rule is obs[t] + actions[t] → obs[t+1]. The in-browser recorder follows it exactly; its "key" is the last arrow keydown that arrived during the tick.

5a. Episode: load files without reading them


ep = Episode.load("data/stage1/ep_00001")
ep.obs      # np.load(..., mmap_mode="r")  → shape (501, 2, 45, 45)

Memory-mapping (mmap_mode="r") means the OS reads bytes from disk only when a frame is actually used. The 500 MB of recordings can then be "opened" instantly, without loading them all into RAM.



5b. FrameDataset: the sliding window (k = 2 shown)


One training example = k context frames + the key at the last one → the next frame. Slide it one tick at a time across every episode. These are real consecutive ticks:




   


ds = FrameDataset(find_episodes("data/stage1", "data/human"), k=2)
len(ds)                 # 100,085 examples  (one per tick of every episode)
context, action, target = ds[100]
context.shape  # (2, 2, 45, 45)   k frames × 2 layers × 45 × 45
action         # 4  (LEFT)
target.shape   # (2, 45, 45)


Why k > 1? In the strip above, notice that holding a key moves the player only every other tick. From one frame, the model can't tell whether this tick is a move tick. With two frames, it can see whether the last tick moved. That's H3. At the start of an episode there aren't k frames yet, so the first frame is repeated as padding.



5c. split_by_episode: honest validation


Validation data is held back to measure how well the model handles frames it has never seen. If we split random ticks, tick 41 could be in training and tick 42 in validation. They are nearly identical, so the score would be inflated. We hold out whole episodes instead. The same idea gives the human test set in H6: some of your sessions are never trained on.

5e. What the model actually receives, per cell


The grid stays a grid. Frames, layers, and the key are stacked as channels at each cell, like an image where each pixel has 105 numbers instead of 3 (R, G, B). Click any cell to see its vector. The frames are real ticks (t−1 and t, k = 2) from the sliding-window example above.






CNN layers stacked:  1  → each output cell sees a 3×3 area








Each square is one number in the cell's input: dark = 1, light = 0. "One-hot" means exactly one square per group is on. That is how a category becomes numbers without implying LEFT is "bigger" than UP.






per cell:   8 terrain(t−1) + 42 entity(t−1) + 8 terrain(t) + 42 entity(t) + 5 key  = 105
whole input: 105 channels × 45 × 45      (k = 4 would be 4×50 + 5 = 205 channels)
key:        the same 5 numbers copied into every cell. It has no position, so every cell "hears" it.
            (Alternative to test later: FiLM, where the key adjusts features mid-network instead.)


The sliding window: one CNN layer looks at a 3×3 patch, i.e. 9 cells × 105 numbers, and computes new features for the center cell. The same learned weights are reused at every position. Those weights encode rules like "player facing right, key RIGHT, grass to the right → the player will be there next." Stacking layers grows what each cell can "see" (press + above). About 10 layers covers ±10 cells, the distance at which dinos notice the player.

That single number becomes this cell's value in the filter's output channel. The filter then slides to the next cell and repeats with the same weights. That gives a 45×45 map of "how much grass is to the right" everywhere. With 64 filters you get 64 such maps, and those are the input to the next layer.



6. Error analysis: how the bugs were found


Error analysis is a standard practice: slice the model's mistakes into categories, then slice the biggest category again, until a pattern shows up. No labels are needed beyond what's already recorded (frames and keys). Each question comes from the previous answer. Run it on any checkpoint with uv run python -m tlfp.error_analysis checkpoints/<run>.pt. These are real numbers from stage1-k2-fixes:




Why do this instead of just training longer? It tells you which setting to change. Here it says "more history" (k), not "wider view" (U-Net) and not "more data". That saves many blind training runs.



7. Rolling the dice: argmax, sampling, temperature, top-p


For each cell the model outputs a score per possible class. Softmax turns those scores into probabilities that add up to 100%, like a weighted die with one face per class. These are real probabilities from our trained models for a few interesting cells:















  





argmax = always take the tallest bar. It's deterministic and never surprising. For "grass next to lava" it says GRASS every single tick, so lava never spreads.


sampling = roll the weighted die: pick each class with its probability. GRASS 99.7% / LAVA 0.3% means lava wins about 3 rolls in 1,000. Each cell rolls its own die every tick.


temperature reshapes the die before rolling. Below 1 sharpens it (the favorite gets even more likely; near 0 it becomes argmax). Above 1 flattens it (long shots get likelier, which means more surprises and more noise). Math: divide the scores by T before softmax.


top-p trims the long tail. Keep only the most likely classes until they add up to p (e.g. 90%), drop the rest, and roll among those. It stops 0.01% nonsense from ever happening while keeping real alternatives.




These are the same knobs used in LLM text generation. There, each "cell" is the next word. "Logprobs" are simply the logs of these probabilities.

9. Shrinking the map: what a U-Net does


A conv layer's 3×3 window always covers 3×3 cells of whatever grid it's looking at. Shrink the grid, merging each 2×2 block into one cell, and the same 3×3 window now covers a 6×6 area of the original. Shrink again and it covers 12×12. Click a cell on the full-size map to see what one 3×3 window covers at each size.




full size 45×45
window covers 3×3


shrunk once: 23×23
1 cell = 2×2 original · window covers ~6×6


shrunk twice: 12×12
1 cell = 4×4 original · window covers ~12×12




White box = one 3×3 window at each size. Yellow dashed box on the full map = the area the 12×12-level window actually covers. Here each shrunk cell shows its most common terrain just to make it visible. In the real network each shrunk cell holds a learned summary: 64+ numbers like "lava nearby", "a dino in this block heading east".




Keeping the pretrained weights: with one trick we don't lose the warm start. Build the U-Net so its full-size path is exactly the current CNN, copy those weights in, and start the shrink/grow branch at zero, so it adds nothing at first. At step 0 the new model behaves exactly like the old one, then gradually learns to use the wide view. Without the trick, only the pieces with matching shapes (the input layer and output heads) could be copied.
