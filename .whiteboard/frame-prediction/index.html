Predicting Thunder Lizard frames

Can a neural net learn to be the game engine? Given the last frame(s) and the key you pressed, it draws the next frame. Draw or comment on anything below.

1. The big picture

Tagline: Playing the game inside a neural net.

① Headless harnessRun the real game in Node with no browser, display, or sound. A bot presses keys.
→
② DatasetMillions of (framest-k..t, keyt, framet+1) triples saved as integer grids.
→
③ ModelSmall PyTorch net. Input: grid(s) + key. Output: a guess at every cell of the next grid.
→
④ Play in the netFeed the model its own outputs, so you play the game inside the neural net. That's the portfolio demo.

Known precedents: World Models (Ha & Schmidhuber 2018), GameNGen (Doom running on a diffusion model, 2024), and DIAMOND / Genie. Your version is much easier because a frame is a 45×45 grid of symbols rather than pixels.

2. What I found in the game (and what changes the plan)

FactImpact on the plan
It's not actually turn-based. mainLoop ticks every 70 ms, lava every 50 ms, water every 200 ms. The player moves on keydown, and speed depends on level (MOVMENT_SPEED_BY_LEVEL).We define a "step" as one main-loop tick and record whichever key is held (or NONE). The harness calls the systems in order itself, so wall-clock time doesn't matter.
The viewport is 45×45 and follows the player across a 250×250 map. It zooms to 39×39 when 3+ dinos are near, with animated zoom steps.When you move, a new row of terrain scrolls in and the model can't know what's in it. v1: lock zoom at 45. Unknown edges stay blurry, which is expected.
Much of the rendering is random noise: water/ocean glyphs re-roll every tick, terrain glyph variants are random, tail glyphs flicker 20% of the time, and lava spread is probabilistic.Collapse glyphs into semantic classes (all water = WATER). Otherwise the model wastes its capacity predicting coin flips. Lava is truly stochastic, so the model learns spread probabilities.
60 AI dinos run awareness/pursue/flee systems. A dino is drawn as head, body, legs, and tail around its position, and the facing direction sets the glyphs.This is the hard and interesting part. Dino behavior depends on hidden state such as targets and cooldown counters. Giving the model 2–4 past frames lets it infer momentum.
Everything uses ROT.RNG, which is seedable.Runs are reproducible, which helps with debugging and with building held-out test sets.
Game logic is tied to document, Howler sounds, and ROT.Display.The harness stubs those out. Vitest tests already construct pieces of the game outside a browser, so this is a moderate refactor, not a rewrite.

5. Training loop


for frames, key, target in dataloader:      # frames: [B, k, 45, 45] ints
    x      = one_hot(frames, 16)              # -> [B, k*16, 45, 45]
    logits = model(x, key)                    # -> [B, 16, 45, 45]
    loss   = cross_entropy(logits, target)    # per-cell classification
    loss.backward(); opt.step()




Baseline to beat: "copy last frame"
About 90%+ of cells don't change in a tick, so raw accuracy is misleading. Measure accuracy on cells that changed, and on dino cells specifically.


Rollout drift
Step 1 can look great while step 50 falls apart, because errors compound once the model eats its own output. Fixes: train on short rollouts, add noise to the inputs, or sample instead of taking the argmax.





6. Stack & viability




Data genNode + TypeScript inside your repo (reusing the vite/vitest setup). Write .npy or JSONL shards. At about 1 ms per tick headless, that's roughly a million frames in minutes.


FrameworkPyTorch rather than TensorFlow. It's what most current tutorials, Hugging Face, and research code use. HF's role is optional: host the dataset and model with datasets/huggingface_hub, then demo on a Space.


HardwareThe v1 CNN (about 1–5M parameters) trains on a Mac's MPS GPU in under an hour. The transformer or diffusion variants might want a rented GPU (Colab or HF), at a few dollars.


DemoExport to ONNX and run it in the browser with onnxruntime-web, using your existing ROT.Display renderer. The page shows the "real" and "dreamed" games side by side.


VerdictVery viable. Terrain, player movement, and scrolling will work quickly. Dino AI and lava will be fuzzy at first, and improving them is the learning curve. Each milestone is a demo you can show on its own.

Glossary



Glossary



kHow many past frames the model sees. k = 2 means the current frame plus the one before it. More history lets it infer rhythm and motion (H3).


batch (64)How many examples go through the model at once. The model adjusts after each batch, using the average error.


channelOne number per cell, like one color in an image. Our input has k × 50 + 5 channels per cell.


one-hotA category written as a row of 0s with a single 1 (GRASS = slot 3 on).


filter / conv layerA small learned weight table (3×3 × channels) slid over the grid. Each filter produces one new feature channel. A layer has many filters.


receptive fieldHow far a cell can "see" after stacking layers: 3×3, then 5×5, then 7×7, …


hyperparametersThe settings we choose (k, learning rate, epochs, batch size, loss weighting, width/depth), as opposed to the weights the model learns.


weightsThe numbers inside the filters. Training adjusts them. Everything else (sizes, k, batch) is chosen by us.


head / bodyThe body (backbone) is the shared stack of layers that builds features. A head is a small final layer that turns those features into one specific answer. Ours: a terrain head and an entity head (H11 would split the entity head into three).


logits / softmaxLogits are the raw scores a head outputs. Softmax turns them into probabilities that sum to 100%.


logprobThe (natural) log of a probability. Products of probabilities become sums, which keeps numbers stable.


cross-entropy lossThe training objective: −log(probability given to the true answer). It heavily punishes being confidently wrong. train/loss is its average.


argmax / samplingArgmax: take the most likely class. Sampling: a weighted random pick by probability (rolling the dice).


temperature / top-pKnobs that reshape the dice before rolling: temperature sharpens (<1) or flattens (>1); top-p drops the unlikely tail.


calibrationWhether predicted probabilities match reality: things predicted at 10% should happen about 10% of the time.


epoch / stepEpoch = one full pass over the training data. Step = one batch and one weight update.


validation / overfittingValidation = held-out episodes, never trained on. Overfitting = training loss improves while validation gets worse (memorizing instead of generalizing).


warm start / fine-tuningStart training from an existing model's weights instead of random ones (H4).


rolloutFeeding the model its own predictions tick after tick: playing inside the net.


U-Net / skip connectionA CNN that shrinks the grid to see wide, then grows it back. Skip connections carry full-detail features straight across to the output side.


error analysisSlicing the model's mistakes into categories until a pattern shows up (How it works, section 6).
